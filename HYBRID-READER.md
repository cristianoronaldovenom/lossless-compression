# Verified hybrid reader
Version 1 archive access (S10ARC01) only. Existing CLI v2/v3 paths are unchanged.
Use `const {VerifiedReader}=require("./verified-reader.cjs")`.
`const r=new VerifiedReader("assets.s10",{cacheBytes:16*1024*1024,gpuIndex:true});`
`r.read(offset, length)` returns independently owned verified bytes; `readInto` leaves destination untouched on a verification failure. `readBits(bitOffset,width)` returns an unsigned LSB-first number (1..32 bits); 16-bit requests span two or three 10-bit symbols, including cross-block boundaries. This is an application API, not a kernel driver, memory-mapped game asset provider, or system RAM replacement.
Small reads and raw/deflate/repeated blocks prefer the CPU. Large palette batches can use OpenCL while CPU codecs run. GPU is opt-in and any GPU failure disables it, retries independently on CPU, and verifies against archive SHA-256/128-bit block digests. The index itself is SHA-256 checked. Cache stores verified blocks only and never exposes internal views. File change detection rejects a modified open archive; use immutable trusted files (stat detection is not a cryptographic snapshot or protection against malicious concurrent writes). Hashes detect corruption but are not signatures; an attacker able to replace an entire archive can recompute them. No ECC or power-loss guarantees.
Cache bounded by cacheBytes (default 16 MiB, maximum 256 MiB); maximum request 16 MiB. Temporary allocations and OpenCL device buffers are additional. Synchronous API: use a worker thread for game/render loops. Small reads still check file metadata and cold reads verify whole 64 KiB blocks. Cache does not imply nanosecond application latency. GPU readback is uncompressed and limited by PCIe; GPU resident workloads or compressed transport to CPU use separate existing paths. No claim of universal 10:1 compression or faster existing games.
Benchmark: `npm run bench:reader -- assets.s10 20000` and add `--gpu` for GPU comparison. Reports actual p50/p95/p99 read latency and sequential verified read throughput including copies, file IO, and cache effects. Run separate with cold and warm filesystem cache as needed.
